# V0 architecture and trust boundary

## Data and execution

`Slean/Core.lean` defines case, question, empirical claim, frozen protocol, run, observation, artifact reference, cost, assessment, decision, formal claim reference, relation, dependency gate, and event. Each recorded object has an ID, positive version, domain, provenance, and audience. IDs are unique within a case. A run names one frozen protocol ID. An observation names a run, metric, unit, exact decimal text or unknown state, artifact reference, and UTC time. Artifacts are references and digests, not embedded blobs. Schema 0.3 records explicit `all_of` and `any_of` dependency groups with prior member and target references. `DependencyExpr` remains reserved for future evaluation; a recorded gate is not a proof or a computed verdict.

`step` applies one event without IO or a clock. `replay` folds a prefix in sequence order. Sequence is the authority; UTC timestamps validate causal edges. A changed protocol must have a new ID and version. The exact comparator multiplies integer significands by powers of ten, so it does not round through a binary float. The V0 automatic assessment uses exactly one observation. An external assessment can cite all its prior observations, but cannot become a local `pass`.

Schema 0.2 adds `SourceRecord`: an owner-only canonical JSON string for the source manifest, protocol, or event. The source-trace replay checks exactly one first freeze, source IDs and sequence, protocol digest linkage, prior prediction references with matching observation ID, phase, and condition, one final completion agreeing with the manifest result, and complete typed observation and assessment coverage. Source records are data for this bounded adapter, not a general proof mechanism. Canonical digests are computed by Python; Lean checks relationships among supplied values but has no SHA-256 implementation in the replay. Artifact bytes remain at the source.

The proof `promotionEvidence_has_frozen_observation` says that the executable promotion gate can return a witness only when it finds a passing assessment, its selected observation and run, and the protocol named by both run and assessment. It does not prove that arbitrary State values came from replay, that artifact bytes are sound, or that an empirical finding is true. Replay validation supplies additional tested checks. The compiler checks the proof under Lean's `propext` and `Quot.sound` axioms.

## JSON, CLI, and privacy

`Main.lean` accepts JSON and calls the pure replay function. Matched schema and semantics version pairs `0.1.0`, `0.2.0`, and `0.3.0` are accepted. The owner path rejects unknown fields. There is no migration path yet. `Slean/Export.lean` redacts an owner-only case header, selects agent-visible events, removes unsupported payload keys, drops references to hidden objects, replaces every opaque run input reference with `[redacted]`, and renumbers the visible journal before validation and view calculations. A gate is projected only when its target and every member remain visible. Source records must be owner-only and never enter an agent projection. Hidden values, private digests, and private provenance do not enter an agent view. The owner remains responsible for marking visible objects for the right audience.

`Slean/Proof.lean` pins one exact elaborated statement and checks its declaration kind, direct Slean dependencies in the proof term, and axioms during build. `proof` reports `declared` and an attestation eligibility flag for a matching local claim; it never emits a standalone `kernel_checked` status without build identity. A JSON field is treated as a declaration. `tools/attest_proof.py` requires a clean committed tree, runs `lake build`, and promotes an eligible receipt to `kernel_checked` only after linking it to a content-addressed manifest of the source revision, executable, compiled modules, Lake manifest, and Lean toolchain. Each receipt also names the SHA-256 of the audience-filtered canonical export; hidden owner data is filtered before this public hash. These links are produced by trusted Python and Lake code. The exporter and the binding from JSON to the local theorem are ordinary code, not kernel-proved. No `independently_rechecked` result is emitted.

`tools/audit_autoresearch_trace.py` is a read-only development adapter. It converts one source trace in memory, sends it to the CLI over standard input, and emits aggregate counts, check results, and field names in its report. It does not change the source evaluator or save source values. The inspected trace uses a multi-observation decision rule that Slean does not reproduce; see the [gate V retest](docs/gate-v-retest.md).

`timeline` validates the full case, projects it for `agent` by default or explicit `owner`, validates the projection, then applies each projected event with the normative `step` function. It returns the projected case and state snapshots from prefix zero through the last event. `explorer/render.py` consumes only that checked CLI result. It escapes embedded JSON for an HTML script element and writes a local static artifact with no network calls or write path. The page uses the snapshots for its decision and evidence views; it never recomputes a verdict. The owner artifact contains owner data in its HTML, so generating or sharing it is a separate, explicit action. The output marker prevents an agent artifact directory from being silently reused for owner data.
