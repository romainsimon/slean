# Gate V: reduce

This local gate used one existing development trace in read-only mode. The source had `manifest.json`, `protocol.json`, and `events.jsonl`; it contained one freeze, 48 frozen predictions, 48 recorded observations, and one completion event. The source event IDs were unique, sequences were contiguous, the frozen definition matched the protocol file and manifest, and source artifact hashes matched. The source files had identical bytes before and after the audit. Source recorded CPU use was `0.44002399999999997` seconds in its JSON; host cost and this task's human labor cost are unknown.

The adapter made a 197-event Slean case in memory and Slean accepted its structural replay. The original data and evaluator were not changed. The converted case was not saved or exported. Its assessment referenced only the last observation and was `external_unverified` because the source decision depends on a model comparison, priors, posterior probabilities, an audit, and many observations. Model predictions, conditions, phases, audit adequacy, some evaluator hashes, most manifest fields, and subsecond time precision were not represented as decision data. The [adapter](../tools/audit_autoresearch_trace.py) reports the exact unmapped field names for each run.

On in-memory copies of the actual event shape, Slean rejected a changed unit (`metric_unit`), a missing prediction link (`missing_relation_ref`), and a future observation (`future_observation`). It accepted a changed protocol file and a second freeze event because the adapter does not model those changes as replay events. These were injected probes, not defects found in the original trace. The source runtime's artifact hash verification already detects a changed stored file, and its replay checks the protocol definition. The probes therefore do not establish a new decision control over the existing flow.

[Verso Blueprint](https://github.com/leanprover/verso-blueprint#readme) already handles theorem links, source provenance, formal progress, metadata, and dependency graphs. Its documented interface does not provide this experiment's decision evaluator. That gap alone does not make Slean V0 useful: the inspected trace's necessary decision fields are lost in V0. We did not build a Blueprint prototype on this trace because the loss and lack of a new control fail the preceding value criterion.

**Decision: reduce.** Keep the bounded Lean/JSON validator and this negative result as local research output. Do not start the documentation site, custom Explorer, or 3D. A later program would need a lossless decision model and a demonstrated error that the current source runtime or a reasonable Blueprint extension does not already prevent. This gate is not a scientific result, release, or publication approval.
